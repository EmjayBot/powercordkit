PowerCordKit/ Mail setup

Self-host the Mail inbox

The labs run anywhere static. The Mail inbox (unified triage, tickets, ideas, webhooks) needs one Cloudflare Worker + one D1 database per community. This guide takes you from zero to a live inbox in ~20 minutes. Free-tier friendly.

0What you get

One deployment serves the tools hub + all labs + the Mail UI. The inbox API (/api/*) and webhooks (/hooks/*) run in the same Worker, backed by D1. Two communities = two deployments (e.g. tools.example.com + mod.example.org), each with its own Worker, D1 and secrets — same codebase, two configs (wrangler.jsonc + wrangler.community.jsonc).

1Prerequisites

  • Node.js ≥ 22.12 and a Cloudflare account (free tier is enough).
  • The PowerCordKit repo on your machine.
  • Your community's Discord server + (optionally) Discourse forum admin access.

2Install & log in

git clone https://github.com/EmjayBot/powercordkit.git
cd powercordkit
npm install
npx wrangler login      # opens the browser — pick YOUR community's account
npx wrangler whoami     # confirm the right email + account ID
Running a second community later? npx wrangler logout && npx wrangler login switches accounts. Personal uses wrangler.jsonc; every community gets its own wrangler.<name>.jsonc (copy wrangler.community.jsonc).

3Database

npm run db:create:community          # or: npx wrangler d1 create powercordkit-mail-community --config wrangler.community.jsonc
# paste the printed database_id into wrangler.community.jsonc → d1_databases[0]
npm run db:migrate:remote:community

Schema (migrations/0001_init.sql): inbox_items + notes, prepared statements only. Verify: npx wrangler d1 execute powercordkit-mail-community --remote --config wrangler.community.jsonc --command "SELECT count(*) FROM inbox_items".

5Deploy

npm run deploy:community
# prints e.g. https://powercordkit-community.<you>.workers.dev
curl https://<your-worker>.workers.dev/api/health   # expect {"ok":true,"env":"community"…}

6Custom domain

If the community zone (e.g. your-domain.com) is in this Cloudflare account, add to the community wrangler config and redeploy:

"routes": [{ "pattern": "mail.your-domain.com/*", "zone_name": "your-domain.com" }]

Then add DNS: CNAME mail → <worker>.workers.dev, proxied ON. If the zone lives elsewhere, point a proxied CNAME at the workers.dev hostname instead — the Worker answers on both.

7Connect Discourse

Discourse Admin → API → Webhooks → New:

  • URL: POST https://<your-host>/hooks/discourse
  • Events: post_created, topic_created — categories: your support + ideas categories
  • Secret: paste DISCOURSE_WEBHOOK_SECRET (Discourse sends X-Discourse-Event-Signature: sha256=<hmac>; the Worker verifies with a timing-safe compare, 401 otherwise)

Test: create a forum post, then GET /api/inbox?server=discourse — it should appear with src: "discourse".

8Connect Discord

Your bot (or a context-menu command "Mail to Inbox") POSTs JSON:

curl -X POST https://<your-host>/hooks/discord \
  -H 'Content-Type: application/json' \
  -H 'X-Powercordkit-Secret: <DISCORD_WEBHOOK_SECRET>' \
  -d '{"server":"main","type":"ticket","title":"Spam in #help",
       "content":"User @x posting invites (thread #ticket-128)",
       "author":"mod_bot","by":"auto-capture","url":"https://discord.com/channels/…"}'

Fields: server (default general, configurable via DEFAULT_SERVER), type (idea|support|ticket|mailed), title*, content, author, by, url (jump link), prio. Missing/wrong secret → 401. Auto-capture: call it on MESSAGE_CREATE (ideas channel), THREAD_CREATE (ticket threads).

Multiple servers: no configuration needed — any server value is accepted and GET /api/servers derives the live registry (with per-type counts) from inbox data; the inbox UI builds its filters from it. To scope a bot to one server, mint a per-server token (admin auth = global X-Powercordkit-Secret; shown once, store it):

curl -X POST https://<your-host>/api/servers/my-server/token \
  -H 'X-Powercordkit-Secret: <DISCORD_WEBHOOK_SECRET>' \
  -H 'X-Mod-Key: <MOD_API_KEY>'
# → {"ok":true,"server":"my-server","token":"…"}
# bots then send -H 'X-Server-Token: …' instead of the global secret.
# revoke: curl -X DELETE …/api/servers/my-server/token -H 'X-Powercordkit-Secret: …' -H 'X-Mod-Key: …'

★Bot integration: reading channels

Option A — Cloudflare poller, no hosting (recommended). The Worker itself polls your channels every 2 minutes via the Discord REST API and mails new items straight into D1 — no server, no bot process. One human step: create a Discord app, invite its bot with View Channel + Read Message History on the watched channels, then store its token with wrangler secret put DISCORD_BOT_TOKEN --config wrangler.community.jsonc. Feeds + schedule live in the community config (FEED_MAP, */2 * * * *); progress (last message IDs, seen threads) is tracked in D1 automatically. ~2 min delay instead of instant — the tradeoff for zero hosting.

Option B — self-hosted bot (instant). Below is the complete recipe for a TEP-style setup: two guilds, four watched channels, one inbox. Adapt the IDs to yours.

1. Portal setup — discord.com/developers/applications → your app → Bot: enable Message Content Intent (privileged), copy the bot token. Invite the bot with applications.commands + View Channel, Read Message History on the watched channels.

2. Events to subscribe (discord.js v14 names):

3. Minimal bot (Node 22+, save as bot.cjs, run npm i discord.js@14 — intents: Guilds + GuildMessages + MessageContent):

const { Client, GatewayIntentBits } = require('discord.js');
const HOST = 'https://mod.tep.one'; // your inbox host
const TOKENS = {
  'the-east-pacific': process.env.TOKEN_TEP,   // X-Server-Token per guild
  'tep-urth': process.env.TOKEN_URTH,
};
const seen = new Set(); // in-memory dedupe (threadCreate fires once; messages: skip seen ids)
async function mail(server, payload) {
  const r = await fetch(HOST + '/hooks/discord', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json', 'X-Server-Token': TOKENS[server] },
    body: JSON.stringify({ server, by: 'auto-capture', src: 'discord', ...payload }),
  });
  if (!r.ok) console.error('mail failed', server, r.status, await r.text());
}
const jump = (g, c, t) => `https://discord.com/channels/${g}/${t ?? c}`;
const client = new Client({ intents: [GatewayIntentBits.Guilds, GatewayIntentBits.GuildMessages, GatewayIntentBits.MessageContent] });
client.on('threadCreate', (th) => {
  if (th.guildId !== '633351482128728064') return;
  // report-a-concern → ticket, support-desk forum → support
  const kind = th.parentId === '894920335139409983' ? 'ticket'
    : th.parentId === '1114601767724920893' ? 'support' : null;
  if (!kind) return;
  mail('the-east-pacific', { type: kind, title: (kind === 'support' ? 'Post: ' : 'Thread: ') + th.name.slice(0, 80),
    content: `New ${kind === 'support' ? 'support post' : 'concern thread'} by ${th.ownerId ?? 'unknown'}`, author: th.ownerId ?? 'unknown',
    url: jump(th.guildId, th.parentId, th.id) });
});
client.on('messageCreate', (m) => {
  if (m.author.bot || seen.has(m.id)) return; seen.add(m.id);
  if (m.guildId === '508790398873894915' && ['511665989210079252', '1252432781653315634'].includes(m.channelId))
    mail('tep-urth', { type: 'ticket', title: m.content.slice(0, 80) || '(attachment)', content: m.content.slice(0, 4000),
      author: m.author.tag, url: jump(m.guildId, m.channelId, m.id) });
});
client.login(process.env.DISCORD_BOT_TOKEN);

Run it:

set DISCORD_BOT_TOKEN=… && set TOKEN_TEP=… && set TOKEN_URTH=… && node bot.cjs
# keep it alive (one option): npm i -g pm2 && pm2 start bot.cjs --name modmail && pm2 save

Use the two X-Server-Token values from your handoff pack for TOKEN_TEP / TOKEN_URTH. Then create a test post in support-desk — it should appear in the inbox within seconds (archive it after).

Notes for your bot dev: keep seen bounded in production (e.g. an LRU of the last 5k IDs — restarts re-send nothing because messageCreate only fires live). Set prio:"high" when a message mentions @everyone/@here or matches an invite-link regex. Attachments: put m.attachments.first()?.url into content (or url if there's no thread link). The inbox truncates safely (title 300, content 20000) — oversize payloads get 413 past 256KB, bad JSON gets 400, wrong token gets 401.

4. Verify without a bot — copy the curl shape from §8 with your real IDs and one server's X-Server-Token, then check GET /api/inbox?server=the-east-pacific (with X-Mod-Key). Archive the test from the inbox UI when done.

Option C — BotGhost (no code, no hosting). Step by step, per feed (do it 4 times — once per row below):

  1. Dashboard → your bot → invite it to the Discord server if it isn't there (Modules → Invite Your Bot).
  2. Go to Custom Events → click the yellow Custom Event Builder block → pick the trigger: “When a thread is created” (Thread Events) for the two forum channels (report-a-concern, support-desk), “When a new message is sent” (Message Events) for staffing / administration. Name it, e.g. mail-support-desk.
  3. Add a Channel Condition block first: for thread events, condition on the parent channel ID (894920335139409983 or 1114601767724920893); for message events, channel IS exactly the channel ID. This stops other channels leaking into the inbox.
  4. Optionally add a User Condition so the bot ignores its own/other bots' messages ({isBot} is false) — prevents loops.
  5. Add action → Send an API Request → open the Request Builder:
    • URL: https://mod.tep.one/hooks/discord (your host), type POST.
    • HTTP Headers → Add: key X-Server-Token, value = that feed's server token from your handoff pack.
    • Request Body → switch to Raw JSON Body → paste the JSON for your feed (table below). For every {…} value, click it and pick the real variable from the clipboard icon (variable list) — e.g. message text is under the Message object ({Message.content}), author under {Message.author.tag}, IDs under {Message.id} / {channel_id} / {server_id}; thread events expose the thread object the same way.
    • Tick Replace variables in Request Body, then Test Request — expect status 200/201. Check the inbox, archive the test.

Trim titles yourself if needed: our inbox caps title at 300 chars and content at 20000, but a clean title (first ~80 chars) triages faster. A 401 means the X-Server-Token is wrong; 400 means malformed JSON (check Test Request output).

Two caveats: custom events / API actions may require a paid BotGhost plan — if a block is locked, that's why. And BotGhost owns your delivery path, so keep the Cloudflare poller (Option A) as the fallback either way.

★How mail works across multiple servers

One inbox watches many Discord servers (guilds) plus forums. The model is deliberately simple:

  • Open registry, no pre-registration. Every mailed item carries a server string (e.g. a guild slug). The first mail from a new server creates it — GET /api/servers derives the live registry (with open counts and per-type breakdowns) straight from the data, and the inbox filter bar renders from it. Zero config per server.
  • Scoped credentials. Set DEFAULT_SERVER per deployment for items mailed without a server. Bots authenticate per server: mint a token with POST /api/servers/:id/token (admin: global X-Powercordkit-Secret) and send it as X-Server-Token — only that server's mail is accepted with it. Rotate with POST again, revoke with DELETE /api/servers/:id/token. Tokens are SHA-256 hashed in D1; the plaintext shows once.
  • Per-server bot wiring. Run one bot (or one webhook config) per guild; each posts with its own server + token. Suggested mapping: guild slug → server, #ideas → type=idea, support channels → type=support, ticket threads → type=ticket.
  • Lock indicators. Servers with a token row show 🔒 in the inbox filter — at a glance you see which feeds are credential-scoped.
Scaling: the inbox caps reads at 200 items per query and the daily cron purges items older than 90 days — one deployment comfortably covers a community with several busy servers.
